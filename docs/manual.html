What this is

A desktop-first semester planning tool for University of South Carolina students. A student adds courses without committing to sections, optionally locks exact sections, and generates ranked conflict-free schedules. Applying an option updates the weekly calendar, campus pins, walking-route estimates, and a registration handoff with per-CRN copy actions.

Course discovery accepts subject codes, exact courses, ranges, CRNs, and descriptive natural-language phrases. Each result carries live seat availability alongside verified historical grade distributions, professor teaching profiles, and a year-by-season offering-history matrix. A secondary degree planner imports official major maps spanning catalog years 2020-2021 through 2026-2027 and combines them with an uploaded advising transcript. Plans and transcript-derived progress never leave the device.

Architecture in one breath

A static site plus a three-route relay. Everything interactive runs in the browser: search parsing and ranking, the schedule solver, prerequisite evaluation, transcript parsing, degree planning, and offering analysis. Hosting serves files and forwards exactly three validated read-only requests to fixed upstream University addresses, because those APIs do not authorize a cross-origin browser caller. Python is offline build tooling and a parity oracle. No visitor ever executes it, and scripts/build_static_site.py refuses to copy .py, .pyc, .db, or .sqlite into the deployed tree at all.

Why not fully static

classes.sc.edu does not permit browser requests from another origin, and Banner session cookies are HttpOnly/SameSite-restricted, so a page on a different origin cannot reuse a student's registration session even in principle. Live seat counts therefore require something server-side. The answer was to shrink the proxy rather than delete it: three fixed upstreams, no dynamic URL construction, strict schema validation on every body, a 16 KiB cap, a 10-second timeout, same-origin enforcement, and no credential forwarding in either direction. It holds no secrets, no database, and no per-user state — a validating pipe, not an application server.

A second constraint was load on University systems. A shared server cache turns ten students asking the same question into one upstream request; a service worker cache does not. The mitigation is snapshot-first reads. Versioned catalog, grade, offering-history, building, and major-map bundles are served immutable with a one-year cache, the manifest is no-cache so a new release is picked up promptly, and live upstream calls are reserved for seat counts and faculty names.

Reading the data tree

raw/ is what you cannot get back if you lose it. generated/ is what a script rebuilds. The two in between are labelled honestly: curated/ carries human review and interim/ does not feed anything yet. A .gitattributes marks the generated trees -diff -merge linguist-generated=true, so regenerated artifacts stay out of pull-request diffs and a conflict fails loudly instead of splicing two builds together.

Getting started

git clone https://github.com/j-vaught/UofSC_scheduler.git
cd UofSC_scheduler
uv sync

Python 3.12 or newer. Runtime dependencies are jsonschema, openpyxl, pandas, and requests; the dev group adds pytest, ruff, and ty.

Quality gate

uv run ruff format .
uv run ruff check . --fix
uv run ty check .
uv run pytest -q            # 101 passed
node --test tests/*.js      # 238 pass, 0 fail

The JavaScript suite runs on the Node built-in test runner. There is no external framework and no npm install step. tests/conftest.py prepends both the repository root and src/ to sys.path; pyproject.toml sets pythonpath = ["src"] as well.

Serving locally

uv run python scripts/build_static_site.py
uv run python -m http.server 8766 --directory dist/client

Then open http://127.0.0.1:8766. That Python process is a plain static file server for local testing and is not part of the deployment. There is no application server to run.

Two hard serving constraints

dist/client/ must be served from a domain root, because index.html uses absolute /static/ paths and the service worker registers at scope /. And it must be localhost rather than file:// — crypto.subtle is unavailable on insecure origins, and static/js/data-store.js:438 treats that as a hard failure rather than degrading to unverified data.

If you have not built a full release, build_static_site.py refuses to run (validate_source). Use --allow-representative for local validation only.

Runtime architecture

Page load

static/index.html links three stylesheets, then loads 27 classic (non-module) scripts. Order is load-bearing: data-store.js first, then the three runtime cores (runtime/offering-analyzer.js, runtime/transcript-parser.js, runtime/degree-planner.js), then solver-core.js, live-university-client.js, and api.js before any UI layer. Several tags carry hand-maintained cache-busting query strings such as api.js?v=20260718 — these are not build-generated, so they must be bumped by hand when the file changes.

data-store.js instantiates a singleton global.CourseDataStore at load time, so the store exists before any UI module runs. Service worker registration is gated on 'serviceWorker' in navigator && location.protocol !== 'file:'.

Service worker

BUILD_ID is the literal '__STATIC_BUILD_ID__', substituted at build time with a 16-hex digest of every copied file. SHELL_ASSETS lists 38 entries and the install handler does a single atomic cache.addAll — one missing asset fails the entire install.

Non-GET requests return early, so the three relay POSTs never touch the worker.

Manifest and integrity verification

getManifest() serves from memory inside a 5-minute TTL and coalesces concurrent calls through an in-flight map. _loadManifest() is a four-tier fallback ladder — network (no-store) → Cache Storage → IndexedDB → last in-memory record — throwing only if all four fail.

The integrity gate is _verifyArtifact(). It encodes the response with TextEncoder, compares byteLength against the descriptor, then computes crypto.subtle.digest('SHA-256', bytes) and hex-compares against the manifest digest. Verification runs on both the cached and network paths; a cached artifact that fails is evicted and refetched. _activateRelease() retains exactly the current and previous release, which is what lets a browser keep serving the old release if a new one fails validation.

Solver in a worker

api.js owns the boundary. If Worker is undefined it calls SolverCore.solve(params) synchronously on the main thread; the same fallback catches worker-construction failure. Otherwise it lazily constructs one long-lived worker, correlating requests through a monotonic sequence and a request map. An error event rejects every in-flight request, terminates, and nulls the worker so the next call rebuilds it.

solver-worker.js is 16 lines: importScripts('/static/js/solver-core.js') and a message handler returning {id, result} or {id, error}. Transcript, degree-planning, and offering-analysis use a parallel but separate mechanism keyed by kind, with the same fallback-to-core behavior.

Parity oracles

src/scheduler.py, planner.py, transcript.py, and offering_analyzer.py are executed by the JavaScript suites through importlib, and their outputs are asserted against the browser implementations. They are the correctness baseline for the client solver, not a second runtime. Note that nothing in the repository contains the literal text scheduler.py — the modules are referenced by bare string through dynamic import, so a filename grep will not find these call sites.

Relay & upstream APIs

The relay is not a committed file

dist/server/index.js is written at build time from the SITES_WORKER string constant in scripts/build_static_site.py — a roughly 340-line JavaScript program embedded in a Python string literal. All relay behavior changes are made in that Python constant. It is covered by tests/test_sites_relay_worker.js.

Shared contract

Applies to all three routes.

  • POST only. Anything else is 405 with Allow: POST.
  • Content-Type must start with application/json, else 415.
  • Body cap 16 KiB, checked on both Content-Length and actual encoded bytes, else 413.
  • Same-origin only. A mismatched Origin or Sec-Fetch-Site: cross-site is 403. There is no CORS allowance.
  • Credentials never forwarded. The upstream fetch sends only Accept and Content-Type. Upstream Set-Cookie never reaches the client.
  • Timeout 10 s via AbortController → 504; other failures → 502.
  • Term format /^\d{4}(?:01|05|08)$/. Nothing else is a valid term anywhere in the relay.

Banner field notes

Hard-won reverse-engineering detail. Where the historical capture notes disagree with the code, the code is authoritative and the discrepancy is called out.

Term codes

YYYYMM, where 01 = Spring, 05 = Summer, 08 = Fall. Both live code paths — the worker's validTerm and TERM_RE in scripts/build_offering_history.py — accept only these three suffixes.

Corrections to the old capture notes

The claim that 06 = Summer I and 07 = Summer II is unsupported by any code here; a 202606 term is rejected with a 400 before it reaches Banner. The srcdb: "999999" all-terms sentinel appears nowhere and fails validation. The FOSE details body was documented with key and matched fields — the relay returns 400 for either extra key. The documented FOSE criteria list omitted crn, which the browser actively uses, and included five fields the relay rejects.

Session behavior

Offline pullers do the full dance: GET /classSearch/classSearch to mint a cookie, then POST /term/search?mode=search with mepCode=COL. The term is sticky on the session, which is why a fresh session is created per term and never shared.

The single most useful quirk

getFacultyMeetingTimes needs no session at all. The relay calls it cold with only term, courseReferenceNumber, and mepCode=COL, no cookie, and the tests assert this. It is the one JSON endpoint that works unauthenticated from an arbitrary origin — which is why the faculty route can exist at all.

Traps

  • mepCode vs txt_campus. mepCode=COL is the session/tenant selector; txt_campus=COL is the search filter. Not interchangeable.
  • Faculty is always empty in search results. Instructor identity requires a per-CRN call. This is why the relay caps at 12 CRNs and why grade matching needs a SQLite cache.
  • Only getFacultyMeetingTimes returns JSON. Every other Banner detail endpoint returns HTML fragments, so they could not be relayed as-is even if a route existed.
  • Numeric fields arrive as decimal strings. IDs come back with a trailing .0; both the worker and normalize_code strip it. The same contamination appears in the Excel grade spreads.
  • primaryIndicator is not reliably boolean. Accepts true, "true", "yes", "y", "1".
  • CRNs are exactly 5 digits. Hard-coded in two regexes; 4 or 6 digits is a 400.
  • pageOffset is a row offset, not a page number. Both pullers use pageMaxSize=500.

Pagination paranoia, and why

pull_banner_term_sections.py treats the response envelope as a trust boundary. It verifies the echoed offset matches the request, the echoed page size is exactly 500, totalCount never changes mid-download, each page returns exactly min(500, total − offset) rows, sectionsFetchedCount == totalCount, the final row count equals totalCount, and CRNs are unique across the term. A term is written only if every one of those holds, and only via an atomic os.replace. That exists because Banner will return a short page or a silently truncated result set rather than an error, and will shift totalCount underneath you if the term is being edited.

Rate limits

Banner refuses connections under sustained rapid requests. Observed working settings: 2 worker threads per term, 8 concurrent page fetches within a term, exponential backoff at 0.5 × 2^attempt over 4 attempts, 60 s page timeout, 45 s faculty timeout. Both pullers set a descriptive User-Agent; the default python-requests value is worth avoiding. grade_pipeline.py discards and rebuilds its thread-local session on retry, because a session that has started failing usually stays failed.

Grade spread specifics

Join key is SUBJECT + COURSE_NUMBER + COURSE_SECTION_NUMBER against Banner's subject + courseNumber + sequenceNumber, with sections zero-padded to three characters because Excel stores 1 where Banner says 001. _GF columns are grade-forgiveness counts. J60/J50 are distance sections and usually carry no grades. Public aggregates are suppressed below 10 counted grades.

Stage 14 is one in-process step

build_static_release.py imports the shard builders as functions and calls them directly. There is no subprocess orchestration. --release-id is required; --history-cache and --term-dir are mutually exclusive and one is mandatory. scripts/build_data_manifest.py is not part of this — the manifest is built inline. It is a standalone recovery path that rescans an existing release tree.

Integrity primitives

All in scripts/static_release.py: canonical_json_bytes() (sorted keys, compact separators, for reproducible digests), sha256_bytes(), write_immutable_json() (content-addresses the filename), verify_artifact() (re-reads and re-hashes), and write_manifest_atomic() (mkstemp + fsync + os.replace + directory fsync). The manifest is written last, which is what makes release activation atomic.

Stage 15 builds into a temp staging directory, copies index.html to both client/index.html and 404.html, filters forbidden suffixes, substitutes the build ID (raising if the placeholder is absent), writes _headers with CSP and immutable cache rules, emits the server bundle, re-scans staging for forbidden files, and atomically replaces dist/ with rollback.

A fresh clone cannot rebuild a full release

data/grade_matching_cache.sqlite is gitignored despite being the default history input for stage 14, and it is absent from the working tree. Two recovery routes exist, both requiring live network access: rerun src/grade_pipeline.py, which rebuilds the cache as a side effect of stage 5, or bypass it with pull_banner_term_sections.py → build_static_release.py --term-dir. Neither is a pure-offline rebuild. This is the single largest reproducibility gap in the project.

Major map extraction

Extraction converts one official PDF into one JSON document. The model receives exactly four inputs: the PDF, its manifest row, schemas/major_map_llm_v1.schema.json, and the prompt below. Exactly one result is written per map; filename and map_id must match the manifest, maps are never combined, and one map must not influence another.

Schema contract

additionalProperties: false at every level. Top-level required keys: schema_version, map_id, source, program, plan, requirements_outside_plan, footnotes, review.

Validation gates

Four layers, in order. normalize_llm_major_maps.py canonicalizes in place and raises on the first schema violation. validate_llm_major_maps.py --require-complete checks every file against both schema and source manifest. materialize_llm_major_maps.py raises on PDF SHA-256 mismatch, so a record can never drift from the document it claims to describe. validate_major_maps.py cross-checks course codes against the active catalog release — the last run checked 26,765 codes, matched 25,638, and left 1,127 as historical-or-unmatched with 0 blocking errors.

Review policy

ready only when all published semesters are present, credit totals are internally consistent or explained, every requirement has evidence, and no unresolved logic affects degree progress. needs_review when any wording, footnote, course number, or credit value is uncertain. blocked when pages are missing or unreadable, or program identity cannot be established. The JSON is an extraction artifact, not an authoritative audit — the official PDF remains the source of truth.

Extraction prompt

You are converting one official University of South Carolina major-map PDF into a single JSON document. Return JSON only. The result must validate against schemas/major_map_llm_v1.schema.json.

You will receive the PDF and one manifest record. Copy map_id, catalog_year, pdf_path, pdf_url, sha256, and page_count from the manifest exactly. Extract information only from the supplied PDF. Do not use knowledge from other programs, catalogs, websites, or earlier documents.

Preserve the published semester order and every curriculum requirement. Each requirement must contain the cleaned display label, the original source wording, its credit range, critical-course marker, minimum grade, requirement codes, a normalized rule, confidence, review flags, and at least one evidence quote with a one-based PDF page number.

Represent logic exactly. Use course for one explicit course. Use all_of only when all children are required. Use one_of when exactly one alternative must be chosen. Use any_of when the source permits one or more alternatives without an exact count. Use n_of when the source states a number or range of selections. Use attribute for Carolina Core or another coded attribute. Use elective only when the PDF defines an elective category or filter. Use unresolved when the wording cannot be represented without guessing.

Never turn a general label such as elective, major course, cognate, minor course, Carolina Core requirement, or approved course into a specific course unless the PDF explicitly identifies the allowed course. Never infer prerequisites or corequisites from subject knowledge. Extract them only when the PDF or its footnotes state them. Do not convert a slash, comma, plus sign, or the word "or" into a logical relationship without reading the entire row and relevant footnotes.

Footnote numbers attached to labels are markers, not part of course titles. Remove the marker from the normalized label, preserve the full footnote separately, and list the requirement identifiers to which it applies. Preserve credit ranges exactly. A blank credit cell becomes null, not zero. A zero-to-three range remains zero to three.

Concentrations must be explicit. If the map has no concentration, return an empty array. Do not create a concentration named "None." When a document contains several pathways, retain every explicitly named pathway and identify uncertainty in the review section.

Set requirement confidence between zero and one according to the clarity of the PDF. Confidence below 0.90 requires at least one review flag. Add a review issue whenever the extraction depends on ambiguous layout, broken text, an unreadable symbol, an unresolved footnote, inconsistent totals, or uncertain program metadata.

Before returning the JSON, verify that semester numbers are ordered, identifiers are unique, every evidence page is within the source page count, minimum credits do not exceed maximum credits, logical groups are not empty, and the review status reflects all unresolved issues. Return no prose, Markdown, or code fence around the JSON.

Header "MY COURSES (5)" with the count in parentheses and total credits right-aligned; tags showing only the course code and a small ✕, wrapping horizontally, each colored to match that course's calendar block. Visible only in the schedule state. Shipped instead: a vertical list with REMOVE buttons and no color matching.
  • OpenPlan navigator bar — SCHEDULE ◄ [1] of 23 ► [APPLY]. The [1] is an editable field so a student can jump directly, which matters with hundreds of plans. Plan 1 is always the student's manual picks. Shipped instead: a scrollable card list with SHOW MORE.
  • OpenPreview vs applied semantics. Navigating away while previewing should snap back to the applied plan; adding a course while previewing should add it to the applied plan. Preview block styling exists; these rules do not.
  • OpenPreview mode indicator. Three options were offered and left to implementation: a grid background tint, a banner reading "Previewing Plan 3 — click Apply to use this schedule", or a prominent [APPLY].

  • OpenGrid block popup actions — course code and section, instructor and meeting time, then Fix Section (toggling to Unfix), View Details, Remove. Shipped instead: a large modal with no fix or remove actions.

  • OpenCondensed offering-history summary. A ⚠ next to the header when a course is offered under roughly half the time, meaning "Rare — take it when you can"; a summary line Typically: Fall only | 3 of 16 terms (19%); a last-offered line; and a Show full history expander.
  • OpenDelivery method in the title bar only when not face-to-face, since face-to-face is the assumed default.

Known issues

Resolved defects

Four defects were found while verifying this manual and have since been fixed. They are recorded because each was invisible from normal use, and the shapes are worth recognising again.

Fixed — export.js was entirely unreachable

static/js/export.js was loaded and Export.init() ran, but all nine element ids it binds were absent from index.html. Every getElementById returned null and every binding was silently skipped, so a complete ICS calendar export plus plan save, load, delete, and JSON import/export — 213 lines of working code with its CSS already written — had no way to be invoked. The controls now live in the schedule tab: an Export Calendar button beside Registration Info, and a collapsible Saved Plans panel. The vestigial btn-export-quick lookup, a duplicate of btn-export, was removed rather than given invented UI. tests/test_export_wiring.js now asserts that every id Export looks up resolves in index.html and receives a handler, so this cannot silently rot again.

Fixed — carolina-core.js missing from the precache

It was the only index.html script absent from SHELL_ASSETS. It worked online, because the fetch handler matches any /static/js/ path with stale-while-revalidate, but the Carolina Core requirement picker failed on a cold offline start. It is now precached, and a sweep confirmed no other script is missing.

Fixed — credentials sent on cross-origin bulletin calls

live-university-client.js set credentials: 'include' unconditionally, including on direct cross-origin calls to academicbulletins.sc.edu. With mode: 'cors' that obliges the upstream to answer with both Access-Control-Allow-Credentials: true and a specific non-wildcard origin; a wildcard makes the browser reject the response, silently degrading bulletin lookups to the static catalog. Credentials are now sent only when the endpoint is same-origin. Relative endpoints count as same-origin, absolute ones must match the configured origin, and an unknown origin is treated as cross-origin because that is the safer default.

Fixed — calendar course colors

Course blocks drew from ['#73000A', '#1a4a8a', '#2e7d32', …] — garnet first, then off-brand Material entries. Assignment now follows the documented order: Atlantic, Congaree, Horseshoe, Rose, Honeycomb, then Warm Grey for the sixth course and beyond. Garnet is no longer reachable as a course color. Note the change from modulo cycling to a fixed overflow color: a seventh course now shares Warm Grey with the sixth rather than wrapping back to Atlantic and colliding with the first.

Inconsistencies worth resolving

  • CSP drift within one file. The worker header block omits banner.onecarolina.sc.edu from connect-src; the _headers block includes it. The worker runs first and its headers win, so the _headers entry is stale and grants a permission no browser code uses.
  • build_data_manifest.py duplicates the integrity primitive with a raw hashlib call instead of importing static_release.sha256_bytes. Harmless today; a second implementation of the thing that guarantees correctness is worth collapsing.
  • build_embeddings.py documents an output it never writes — the docstring advertises word_embeddings.json, which no constant produces.
  • planner.py's local map loader is stale. It does a flat os.listdir over its maps directory, but maps have lived in catalog-year subdirectories for some time, so it finds nothing. Left unchanged rather than modified inside a parity oracle.
  • Manual cache-busting query strings on several <script> tags are hand-maintained and will silently go stale, unlike the build-generated service worker BUILD_ID.

Design notes that the code contradicts

  • StalePreference-based ranking was recorded as "explicitly removed from scope." The solver implements it in full, with a preferences modal and an avoid-times grid. The code is the reliable witness; the note is stale.
  • StaleMobile and tablet layout listed as open. It was in fact decided against — the product renders a "Desktop browser required" gate at 720px and below.
  • StaleNavigation structure. The notes documented tabs as HOME | DEGREE PLAN | BROWSE | SCHEDULE | PROFILE | EXPORT and recommended collapsing them. Shipped is a third structure entirely: SEARCH | DEGREE PLAN | SCHEDULE. Both lists in the notes were inaccurate, and "the Browse tab" no longer exists under that name.
  • Stale"All features are built." Directly contradicted by the same document's own nine-item remaining-work list.
  • Stale[+] / [╳] button vocabulary. The notes carry a self-correction about which symbol appears on conflicting sections. The shipped UI uses neither — it uses ADD/REMOVE text and a section dropdown — so the correction is moot.

Conventions

Things whose names are load-bearing

  • static/ — every asset URL in index.html, the service worker precache, and 31 JS modules is an absolute /static/… path, and the release manifest bakes the prefix into all 509 artifact URLs. Renaming means a full release rebuild and a service-worker cache invalidation for every existing visitor.
  • scripts/ — from scripts.X import Y appears in eight files plus tests, via scripts/__init__.py.
  • tests/ — pyproject.toml sets testpaths = ["tests"], and two JS suites resolve paths from the repository root.

Colors

Garnet #73000A is reserved for application chrome and must not be used as a per-course identifier. Course colors are assigned in order: Atlantic #466A9F, Congaree #1F414D, Horseshoe #65780B, Rose #CC2E40, Honeycomb #A49137, then Warm Grey #676156 for the sixth and beyond. No rounded corners on any figure or interface element. High contrast throughout.

Repository weight

Everything stays in version control, raw inputs and generated output alike. The working tree is roughly 740 MB and the pack around 240 MB. No single file approaches the 100 MB hard limit — the largest is grade_analytics.json at 22 MB — so nothing is at risk of rejection.

Consumers who do not need the data tree can use git clone --filter=blob:none or git sparse-checkout set static src scripts tests docs. Prefer rebuild_major_map_release.py over full rebuilds where possible: it carries unchanged artifacts forward by copy, so identical content re-hashes to identical filenames and git stores nothing new. Full release builds are what grow the pack.
